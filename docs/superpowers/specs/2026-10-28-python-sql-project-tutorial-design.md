# Python 与 SQL 项目实战教程设计

## 背景

当前项目「序 / XU」是 React Native + Expo Todo App，后端使用 Python 3.11、FastAPI 和 SQLite。后端已经包含用户、会话、OAuth 状态、一次性登录码和 Todo 数据模型，以及认证、CRUD、事务、参数化查询、用户隔离和 pytest 测试，适合作为 Python 与 SQL 的贯穿式实战案例。

## 教程定位

- 读者：具备少量编程基础，希望结合真实项目学习 Python 与 SQL 的开发者。
- 深度：项目实战，不写成零基础语法大全，也不只做速查表。
- 学习主线：App 请求 → FastAPI 路由 → Python 业务逻辑 → SQL → SQLite → JSON 响应。
- 核心成果：读者能够读懂现有后端，编写安全的数据库语句，并完成常见查询与后端小改动。

## 交付物

在项目内新增一份中文 Markdown 教程：

`docs/python-sql-project-tutorial.md`

教程中的源码引用、字段名、接口路径和命令均以当前项目为准。不修改现有前端或后端业务代码，不改动真实开发数据库。

## 内容结构

### 1. 项目与学习路线

- 说明学习目标和预备知识。
- 介绍 `server/app/` 各模块职责。
- 提供后端启动、API 文档和健康检查方法。
- 用 Todo 列表请求说明完整数据流。
- 对应前端 `src/api/todos.ts` 与后端 `/api/todos` 路由。

### 2. 结合源码学 Python

以项目代码为例讲解：

- 基本数据类型：字符串、整数、布尔值、`None`。
- 容器：列表、字典、元组、集合。
- 函数、参数、返回值、模块与相对导入。
- 类型标注、联合类型、`dict`、`list`、`tuple` 等泛型写法。
- 类、Pydantic 模型和冻结数据类。
- 迭代器、生成器及依赖注入中的 `yield`。
- 上下文管理器、`try/finally`、事务中的 `try/except`。
- 异常与统一 API 错误。
- `sqlite3.Row` 到 JSON 字典的转换，以及数据库 `snake_case` 到接口 `camelCase` 的映射。

主要源码：`config.py`、`db.py`、`deps.py`、`errors.py`、`todos.py`、`auth.py`。

### 3. 结合数据模型学 SQL

- 表关系：`users`、`sessions`、`todos`、`oauth_states`、`login_codes`。
- DDL：建表、主键、自增、非空、唯一、检查、外键和默认值。
- 查询：字段选择、`WHERE`、比较运算、`ORDER BY`、限制返回数量。
- 写入：`INSERT`、`UPDATE`、`DELETE`。
- 关联：`sessions` 与 `users` 的 `JOIN`。
- 聚合：`COUNT`、`MAX`、`COALESCE` 和分组统计。
- 条件更新：一次性登录码的 `used_at IS NULL`。
- UPSERT：Google 用户的 `ON CONFLICT ... DO UPDATE`。
- 索引：结合 Todo 列表和会话查询解释复合索引的用途。
- SQLite 设置：`foreign_keys`、WAL、`busy_timeout`。

### 4. 完整拆解 Todo CRUD

逐一分析列表、创建、更新、删除和清除已完成任务：

- 请求参数与 Pydantic 校验。
- 当前用户获取和 `user_id` 条件。
- SQL 执行、结果读取与响应转换。
- `201`、`204`、`400`、`404`、`422` 等状态码的业务含义。
- 空标题、空更新、任务不存在和跨用户访问等异常路径。
- 乐观更新只在前端调用链中说明，不把前端缓存行为误写成数据库事务。

### 5. 安全与可靠性

- 值必须使用参数化查询，避免 SQL 注入。
- 动态字段名只能来自服务端白名单，不能直接接收用户输入。
- 查询、更新和删除 Todo 都必须限定 `user_id`。
- 写操作使用 `BEGIN IMMEDIATE`，成功提交、异常回滚。
- 数据库只保存令牌和登录码哈希，不保存原始值。
- 外键、事务和测试各自解决的问题及边界。

### 6. 实战练习与参考答案

练习使用临时 SQLite 数据库或项目测试夹具，不直接操作 `server/data/app.db`：

1. 查询指定用户的任务总数、已完成数和完成率。
2. 查询进行中任务并稳定排序。
3. 为任务列表增加安全的分页 SQL。
4. 清理过期会话，并说明是否应在事务中执行。
5. 识别并修正缺少 `user_id` 条件的危险语句。
6. 综合练习：解释创建 Todo 时计算 `position`、插入记录、读取结果的完整过程。

每个练习包含目标、提示、参考 SQL 或 Python、验证方法。扩展改动以独立示例呈现，不直接修改项目业务代码。

### 7. 速查与排错

- 项目常用 Python 写法速查。
- 项目常用 SQL 语句速查。
- 常见错误：数据库锁、外键未开启、空值处理、布尔值与整数转换、时区字符串比较、路径与虚拟环境、跨用户查询返回 404。

## 编写原则

- 每个概念先说明项目用途，再给出精简代码和解释。
- 摘录项目源码时保持语义准确，并标注文件位置。
- 改写示例明确标为「练习示例」，避免与现有源码混淆。
- 命令从仓库根目录或 `server/` 目录运行时，明确当前目录。
- 示例数据不包含真实令牌、密钥或用户隐私。
- 不引入新的运行时依赖。

## 验证方案

1. 核对所有文件路径、接口路径、字段名和表结构与当前源码一致。
2. 对独立 Python 示例进行语法检查。
3. 在临时 SQLite 数据库中执行教程 SQL，核对结果和行数。
4. 运行后端现有 pytest 测试，确认教程编写未影响业务。
5. 检查 Markdown 代码块、章节链接、命令目录和练习答案是否完整。

## 验收标准

- 教程覆盖 Python、SQL、FastAPI、SQLite 与前端调用的完整链路。
- Todo CRUD 和用户隔离均有可运行示例。
- 所有练习都有参考答案与验证方法。
- 不修改业务源码，不触碰真实开发数据库。
- 示例通过语法或执行验证，后端现有测试保持通过。
